EazySchool 360 — Production Audit (Milestone 12)

2026-10-10 · Recommendation: NOT READY FOR RELEASE · Nothing was deployed or written to live data.

Executive summary

Source, rules and tests were re-verified for Milestones 0–11. No confirmed cross-school data access and no financial-integrity defect were found; a generic sweep attacked 64 Firestore collections and 10 Storage paths with 10 foreign actors. Release is blocked by configuration and operations only the owner can supply: placeholder Firebase options in every environment, no release keystore, backups/monitoring unconfigured, no run against a real Firebase project, and a decision on parents' school-wide read scope (F-SEC-3).

Milestone 12A update — blocker closure

Recommendation remains NOT READY FOR RELEASE; the remaining blockers are owner/operations actions, not known code defects.

  • F-SEC-3 fixed (class/section least privilege via parentAccess index; school-wide announcements kept); 14/14 rule mutants killed; cutover needs a per-branch “Refresh parent access” before rules deploy.
  • F-FIN-1 assessed: threat model and phased backend plan written; no financial migration performed.
  • F-DEP-1: OSV scan of 125 Dart packages found 0 advisories; npm audit: 5 high in test tooling only. CI steps added.
  • F-OPS-1/2: validated locally (hosting emulator headers, SPA rewrite, cache); two CI-breaking defects fixed (git-ignored option files; Firebase options model).
  • F-DATA-1: exact PITR/backup/restore procedure documented; not enabled or rehearsed.
  • Tests: Flutter 877 → 882, rules 281 → 290, all passing. Release builds: web ✓, APK ✓ and AAB ✓ (debug-signed), iOS blocked.

Security audit results

  • Cross-school: all reads/writes denied in every branch collection and Storage path (automated).
  • Cross-branch: writes denied everywhere; reads limited to documented exceptions (leave type names, parent-addressed published content/schedules — F-SEC-3).
  • Session: account switch, sign-out and signed-out deep links covered by widget tests; no secrets in source.
  • Untested: OAuth authorised domains, platform registrations, live Firebase.

Financial-integrity verification

33 emulator tests (arithmetic, numbering, concurrency, idempotency, immutability, reversal, waiver, void, audit log) pass; read-only InvoiceReconciler added with 8 tests and a documented procedure. Residual: no trusted backend for independent totals/numbering.
