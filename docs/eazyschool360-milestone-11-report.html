Parent–teacher communication verification

  • Only a linked, ACTIVE, portal-enabled parent of an ACTIVE placed child, with an opted-in teacher who holds the slot; one child per conversation.
  • Only participants read/post; administrators read only after a member reports (audited); no edit/delete; closed conversations take no messages; only the teacher reopens/archives.
  • Unread counters move atomically with the message; a reader clears only their own.
  • Attachments: participant-only, create-only while OPEN, type/size limited.

Security and tenant verification

  • Cross-school, cross-branch, finance, non-participant, ended-link, withdrawn-child and unassigned-teacher cases tested against Firestore and Storage rules.
  • Notification navigation never treats a stored id as authorisation; routes and rules re-check on open.

Known issues / manual setup

  • Push, attendance/fee notices, retention cleanup not implemented.
  • No attachment on a conversation's first message; admins cannot read attachments of reported conversations.
  • Deploy rules, indexes (+2) and storage rules; teachers must switch on Parent messages.
  • iOS build blocked: iOS 26.5 platform not installed.
