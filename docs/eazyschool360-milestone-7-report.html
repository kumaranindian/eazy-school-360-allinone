Tests

  • Flutter: 575 passed (465 before this milestone, +110): 56 unit (incl. the Dart→rules contract export), 48 leave widget, 5 attendance-integration, 1 permission matrix.
  • Rules (emulator, serial): 171 passed: 33 leave rules, 3 leave Storage rules, 1 contract, plus all earlier milestones.
  • Rules mutation check: 10 of 10 mutants killed.

Security verification

  • Tenant and branch isolation tested with direct reads and writes (School B, South branch).
  • Parent ↔ child enforced on read and create; unlinked/portal-off links refused.
  • Applications private: teachers, finance and other parents denied; calendar entries carry no reason/type/document.
  • Reviewer-only decisions; applicant and staff subject cannot decide their own; concurrent decisions: exactly one wins.
  • Balance moves only with its ledger entry; consume/restore ids derive from the application (no double deduction/restore).
  • Documents: only the applicant creates, only applicant + reviewing admins read; no overwrite/delete.
  • Rules mutation check: 10 mutants, all killed.
  • Dart↔rules contract test replays the documents the Dart code writes through the real rules.

Schema and indexes

  • Collections (branch-scoped): leaveTypes, leaveApplications, leaveHistory, leaveCalendar, leaveDayLocks, leaveBalances, leaveLedger, leaveSettings, notifications.
  • Indexes: +26 (56 total) — not exercised by the emulator.
  • Storage: schools/{s}/branches/{b}/leaveDocs/{applicantUid}/{applicationId}/{file}.
  • Leave counted in half-day integer units; dates are civil keys + UTC-midnight timestamps; leave year = academic year.

Bugs found by the tests and fixed

  • Approval could skip the balance move (rule tightened; mutation-checked).
  • Any signed-in school member could plant a notification (creator and event type now tied).
  • Storage allowed overwriting a leave document (create-only now).
  • Dart did not write decidedBy on create, so every submission would have been refused by the rules (found by the contract test).
  • History query could not be proven readable for applicants (subject now pinned in the query; found by the query-shape test).
  • Reports and leave-type dropdowns overflowed on narrow widths; apply-form document row overflowed on phones.

Deployment prerequisites

  1. firebase deploy --only firestore:rules,firestore:indexes,storage and wait for the indexes.
  2. Create leave types in Leave types & policy (nothing is seeded or hard-coded).
  3. Optionally enable "office staff may file student leave on behalf".
  4. Staff need a staff record linked to their login; parents need an ACTIVE portal link.
  5. Run the rules suite serially with project id demo-eazy-school-360.
