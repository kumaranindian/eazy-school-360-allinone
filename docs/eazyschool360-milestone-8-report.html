Tests

  • Flutter: 669 passed (575 before this milestone, +94): 55 unit (incl. the Dart→rules contract export), 39 timetable widget tests.
  • Rules (emulator, serial): 193 passed: 21 timetable rules, 1 contract test, plus all earlier milestones.
  • Rules mutation check: 10 of 10 mutants killed.

Conflict-detection and security verification

  • Tenant and branch isolation tested with direct reads/writes (School B admin, South branch admin).
  • Only managers create/edit/publish/withdraw; teachers and parents cannot write; finance has no timetable access.
  • Publish needs the lock bump + history + draft state; two concurrent publishes: exactly one commits.
  • Entries only while a draft; each cell's teacher must be the section's ACTIVE assignment holder; live flips tied to the parent's status.
  • Replacing another section's timetable is refused; published versions immutable; history append-only.
  • Substitutions: live cell of a published timetable covering the date, ACTIVE teacher ≠ original, one per slot/date, day-sequence bump, history.
  • Notifications tied to the event and writer; forged notices refused.
  • Rules mutation check: 10 mutants, all killed. Dart-written documents replayed through the real rules for every workflow.

Limit: rules cannot query other timetables, so cross-timetable teacher/room double-booking is verified by the client under a branch publication lock (a validation against an older published set cannot be committed), not by rules. Preventing a modified client from skipping it needs a trusted backend.

Rules, indexes and schema

  • Collections (branch-scoped): periodSets, timetables, timetableEntries, timetableCounters, timetableLocks, timetableHistory, substitutions, substitutionDays, substitutionHistory.
  • Notification types added: TIMETABLE_PUBLISHED, SUBSTITUTION_ASSIGNED, SUBSTITUTION_CHANGED, SUBSTITUTION_CANCELLED.
  • Indexes: +5 (61 total) — not exercised by the emulator.
  • Times: minutes since school-local midnight; dates: civil keys + UTC-midnight timestamps.

Bugs found by the tests and fixed

  • A draft's cells could be made live by an 'edit' (rule tightened, mutation-checked).
  • A new version could skip the section counter (rule tightened).
  • Imperative reads of auto-dispose providers could fail mid-load (readAlive helper).
  • A text controller was disposed while its dialog animated out (use-after-dispose).
  • A busy bar animated behind a confirmation dialog (busy only around real work).
  • Phone 'More' menu overflowed with the added destinations (now scrolls).
  • Week navigation overflowed on narrow screens (wraps).

Deployment prerequisites

  1. firebase deploy --only firestore:rules,firestore:indexes and wait for the indexes.
  2. Create bell schedules, then timetables (teacher assignments must exist first), then publish.
  3. Run the rules suite serially with project id demo-eazy-school-360; regenerate the contract fixture with flutter test test/timetable/timetable_write_contract_test.dart after changing what the Dart code writes.

Unresolved issues

  • Cross-timetable teacher/room conflict-freeness and substitute checks are verified by the client under locks, not by rules; a modified client could publish a conflict — trusted backend needed to prevent it.
  • Parents cannot be tied to the child's section in rules: any parent of the school can read published schedule data.
  • No room master data; room conflicts compare free text.
  • No end-to-end run against real Firebase; 5 new indexes unexercised.
  • iOS build blocked by the environment.
  • dart format lib rewrapped 3 pre-existing files (whitespace only), plus the earlier M4 format churn.
